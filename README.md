# Ping check servers OPS

Скрипт на PowerShell для проверки доступности серверов по ICMP (ping).
Список серверов хранится в `Config.json`, результаты выводятся в консоль
и дописываются в лог `ping_log.txt`.

Совместим с **Windows PowerShell 5.1** и **PowerShell 7+**.

## Требования

- Windows 10/11 или Windows Server 2016+ (PowerShell 5.1 встроен).
- Разрешение на выполнение скриптов. Если политика запрещает:

  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
  ```

- Сетевой доступ по ICMP до проверяемых хостов. Если корпоративный firewall
  блокирует ICMP, сервер будет показан как `unavailable`, даже если он работает.

## Файлы

| Файл | Назначение |
|------|-----------|
| `ping_servers.ps1`   | Основной скрипт. |
| `Config.json`        | Список серверов. Создаётся автоматически при первом запуске. |
| `JSON_Conventer.ps1` | Генератор конфигурации по умолчанию. Нужен только если `Config.json` отсутствует или повреждён. |
| `ping_log.txt`       | Лог результатов. Создаётся автоматически, дописывается при каждой проверке. |

Все пути строятся относительно каталога, где лежит `ping_servers.ps1`
(`$PSScriptRoot`), поэтому скрипт можно запускать из любого места.

## Формат Config.json

JSON-массив объектов. Каждый объект — один сервер:

```json
[
    {
        "SID":  "OPS2PRI2",
        "IP":   "172.16.2.1",
        "Name": "DataBase OLTP"
    },
    {
        "SID":  "N/A",
        "IP":   "172.16.2.6",
        "Name": "Kerio VPN, Web-servers"
    }
]
```

Поля:

| Поле   | Обязательное | По умолчанию | Описание |
|--------|:------------:|--------------|----------|
| `IP`   | да           | —            | IP-адрес или DNS-имя. Записи без `IP` пропускаются с предупреждением. |
| `Name` | нет          | значение `IP`| Отображаемое имя сервера. |
| `SID`  | нет          | `N/A`        | Идентификатор сервера (например, Oracle SID). |

Кодировка — UTF-8 (с BOM или без — обе читаются корректно).
Двойная обёртка массива (`[[{...}]]`) автоматически разворачивается.

## Запуск

Из PowerShell:

```powershell
.\ping_servers.ps1
```

Или через `.bat`-обёртку (двойным кликом):

```bat
@echo off
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "%~dp0ping_servers.ps1"
pause
```

### Первый запуск

Если `Config.json` отсутствует, скрипт спросит:

```
Configuration file 'Config.json' not found
Generate new default configuration file? [Y/N]:
```

- `Y` — запускается `JSON_Conventer.ps1`, создаётся `Config.json`,
  мониторинг начинается сразу.
- `N` — скрипт завершается с ошибкой `No configuration`.

Если `Config.json` есть, но повреждён (невалидный JSON, пустой массив,
нет ни одной записи с `IP`), скрипт также предложит сгенерировать новый.

## Управление

После каждого цикла проверки скрипт ждёт нажатия клавиши:

| Клавиша    | Действие |
|------------|----------|
| `Enter`    | Новый цикл проверки (экран очищается). |
| `Spacebar` | Выход из программы. |

Каждый сервер пингуется один раз (`Test-Connection -Count 1 -Quiet`).
Время цикла примерно равно сумме таймаутов по недоступным хостам.

## Вывод

Строка на каждый сервер:

```
[13:10:34]   172.16.2.1      Server DataBase OLTP    |   [SID: OPS2PRI2]   available
```

- **Зелёный** — `available` (ping прошёл).
- **Красный** — `unavailable` (ping не прошёл).

Перед каждым циклом печатается заголовок `=== Ping check servers OPS ===`.

## Лог-файл

`ping_log.txt` дописывается после каждой проверки:

```
[2026-11-05 13:10:34] IP: 172.16.2.1      | Server: DataBase OLTP          | SID: OPS2PRI2  | Status: available
[2026-11-05 13:10:35] IP: 172.16.2.6      | Server: Kerio VPN, Web-servers | SID: N/A       | Status: unavailable
```

Кодировка — **UTF-8 без BOM**, чтобы русские имена читались в блокноте,
VS Code и т.п. Файл не ротируется — чистите вручную или настройте
внешнюю ротацию.

## Решение проблем

### `JSON generator not found: '...\JSON_Conventer.ps1'`

Скрипт не нашёл генератор конфигурации. Положите `JSON_Conventer.ps1`
рядом с `ping_servers.ps1` или создайте `Config.json` вручную
в формате, описанном выше.

### После генерации конфига все серверы `unavailable`, в логе мусор

Была известная проблема старого генератора: он писал JSON в UTF-16
или разворачивал массив, из-за чего `ConvertFrom-Json` возвращал не массив,
а один объект. Текущая версия `ping_servers.ps1` защищена:

- файл читается как UTF-8 (`-Encoding UTF8` снимает BOM);
- результат `ConvertFrom-Json` нормализуется (массив → массив, одиночный
  объект → массив из одного элемента, двойная обёртка разворачивается);
- записи без `IP` пропускаются с предупреждением.

Если проблема воспроизводится — проверьте, что `JSON_Conventer.ps1`
пишет файл так:

```powershell
[System.IO.File]::WriteAllText(
    $path,
    (ConvertTo-Json -InputObject @($data) -Depth 5),
    (New-Object System.Text.UTF8Encoding($false))
)
```

а не через `>` / `Out-File` / `Set-Content` без явной кодировки.

### Все серверы `unavailable`, хотя вручную пингуются

- ICMP блокируется firewall (на клиенте или сервере).
- Между вами и сервером NAT/прокси, не пропускающий ICMP.
- WMI повреждён (в PS 5.1 `Test-Connection` использует `Win32_PingStatus`).

Проверка вручную:

```powershell
Test-Connection -ComputerName 172.16.2.1 -Count 1 -Quiet
```

### `Set-ExecutionPolicy` не помогает (политика задана групповой)

Запускайте через обёртку с `-ExecutionPolicy Bypass` (см. раздел «Запуск»).

### Лог не пишется

Проверьте права на запись в каталог скрипта. Ошибка записи выводится
предупреждением и не прерывает мониторинг.

## Как это устроено

1. **`Config_Initialization`** — если `Config.json` есть, читает и валидирует
   его. Если нет или он битый — предлагает сгенерировать, запускает
   `JSON_Conventer.ps1` через `&` (в отдельной области видимости, чтобы вывод
   генератора не попал в возвращаемый массив серверов), затем перечитывает файл.
2. **`Read-ServerConfig`** — читает JSON, нормализует структуру в массив
   объектов `[pscustomobject]` с полями `IP`, `Name`, `SID`, отбрасывает
   записи без `IP`.
3. **`Main`** — бесконечный цикл: пингует все серверы, печатает результат,
   дописывает лог, ждёт `Enter` / `Spacebar`.
